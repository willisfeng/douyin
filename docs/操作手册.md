# 抖音直播云端录制器 - 操作手册

## 一、项目简介

基于 GitHub Actions 的 24 小时抖音直播自动录制系统。无需登录抖音，通过无头浏览器 + ffmpeg 实现直播流自动检测、分段录制、弹幕采集、语音转文字，全程云端运行。

**核心原理**：Chromium 打开直播间页面 → 每 15 秒检测内嵌 script 中的直播流地址 → 提取最高画质 → ffmpeg 直接下载（不转码，原画质原音质）→ 下播自动停止。

**技术栈**：Python 3.11 + ffmpeg + Playwright + SenseVoice (funasr) + GitHub Actions

---

## 二、系统架构

```
配置层: rooms.txt + requirements.txt
录制层: recorder.py (核心录制) + fallback_upload.py (兜底上传)
转写层: transcribe_release.py / transcriber.py (语音转文字)
索引层: build_releases_index.py / build_transcripts_index.py
前端层: docs/index.html + docs/transcripts.html (GitHub Pages)
```

### 工作流一览

| 工作流 | 触发方式 | 用途 |
|--------|----------|------|
| `continuous.yml` | 每 5 小时自动 + 手动 | 核心录制 + 上传 + 索引构建 |
| `transcribe_release.yml` | 每 30 分钟自动 + 手动 | 音频转文字 |
| `add_room.yml` | 手动触发 | 添加监控房间 |
| `delete_room.yml` | 手动触发 | 删除监控房间 |
| `build_index.yml` | 手动触发 | 重建发布索引 |
| `deploy-pages.yml` | 推送触发 + 每天 | 部署前端页面 |

## 三、环境配置

### 3.1 必需的环境变量（GitHub Actions Secrets）

| 变量名 | 说明 | 获取方式 |
|--------|------|----------|
| `GH_TOKEN` | GitHub Personal Access Token | Settings → Developer settings → Tokens，勾选 `repo` + `workflow` 权限 |
| `GH_REPO` | 仓库名（自动注入 `${{ github.repository }}`） | 无需手动配置 |

### 3.2 可选环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `DOUYIN_COOKIE` | 空 | 抖音 Cookie（base64 编码），用于搜索发现新房间 |
| `BAIDU_APP_KEY` | 空 | 百度网盘 App Key，用于自动备份 |
| `BAIDU_SECRET_KEY` | 空 | 百度网盘 Secret Key |
| `BAIDU_REFRESH_TOKEN` | 空 | 百度网盘 Refresh Token |
| `CHECK_INTERVAL` | 60 | 检测间隔（秒） |
| `MAX_DURATION` | 18000 (5h) | 单个实例最大运行时间（秒） |
| `SEGMENT_DURATION` | 900 | 视频分段时长（秒，默认 15 分钟一段） |
| `OUTPUT_DIR` | /tmp/recordings | 录制文件输出目录 |

### 3.3 首次配置步骤

1. **Fork 本仓库**到自己的 GitHub 账号
2. **创建 GH_TOKEN**：Settings → Developer settings → Personal access tokens → Fine-grained tokens，选择仓库，权限勾选 `Contents: Read and write` + `Actions: Read and write`，生成后复制
3. **设置 Secret**：仓库 Settings → Secrets and variables → Actions → New repository secret，名称填 `GH_TOKEN`，值粘贴 token
4. **配置房间**：编辑 `rooms.txt`，格式为 `房间ID = 主播名称`
5. **启用 Pages**：Settings → Pages → Source 选择 `Deploy from a branch` → 分支选 `main`，目录选 `/docs`
6. **手动触发**：Actions → 抖音直播24小时监控 → Run workflow

## 四、房间管理

### 4.1 添加房间

**方式一**：通过 GitHub Actions（推荐）
- Actions → `add_room.yml` → Run workflow → 输入房间 ID 和名称

**方式二**：直接编辑 `rooms.txt`
- 格式：`房间ID = 主播名称`
- 支持 `=` 或空格分隔
- 支持 `#` 开头的注释行
- 示例：
  ```
  # 海外主播
  215933010618 = 微微在日本农村
  636171657211 = 夏天在越南
  ```

### 4.2 删除房间

**方式一**：Actions → `delete_room.yml` → Run workflow → 输入房间 ID

**方式二**：直接编辑 `rooms.txt` 删除对应行

### 4.3 如何获取房间 ID

1. 打开抖音直播间网页版：`https://live.douyin.com/xxxxxxxxx`
2. URL 中的数字即为房间 ID
3. 也可以在抖音 App 中分享直播间 → 复制链接获取

## 五、录制机制说明

### 5.1 24 小时覆盖机制

- 每 5 小时自动启动一个新实例
- 相邻实例有 30 分钟重叠，确保无缝切换
- 每个实例运行 4.5 小时后自触发下一个实例
- 实例间通过 API 检查，避免重复运行

### 5.2 文件产出

每次直播录制产出以下文件：

| 文件类型 | 命名格式 | 说明 |
|----------|----------|------|
| MP4 | `{房间ID}_{时间戳}_%03d.mp4` | 纯视频，每 15 分钟一段 |
| MKV | `{房间ID}_{时间戳}_%03d.mkv` | 视频 + 弹幕字幕，可开关字幕 |
| WAV | `{房间ID}_{时间戳}.wav` | 16kHz 单声道音频，用于语音转写 |
| ASS | `{房间ID}_{seq}.ass` | 弹幕字幕文件 |
| TXT | 同名 .txt | 语音转写纯文本 |
| SRT | 同名 .srt | 语音转写字幕 |

### 5.3 弹幕字幕

- Playwright 无头浏览器每 1 秒采集一次弹幕和观众数
- 录制结束后自动生成 ASS 格式字幕
- 将 MP4 + ASS 封装为 MKV，播放时可开关字幕
- 弹幕显示：底部滚动，10 行，每条 5 秒

### 5.4 存储位置

- **GitHub Release**：主要存储，每个文件一个 Release tag
- **百度网盘**（可选）：备份存储，按主播名分文件夹

## 六、语音转文字

### 6.1 技术方案

使用阿里达摩院 **SenseVoice** 模型（`iic/SenseVoiceSmall`），通过 `funasr` 框架进行语音识别。

**支持语言**：中文、粤语、英语、日语、韩语等 50+ 种语言。

### 6.2 触发方式

- **自动触发**：录制上传 WAV 文件后，通过 `repository_dispatch` 自动触发
- **定时触发**：每 30 分钟自动扫描未转写的音频
- **手动触发**：Actions → `transcribe_release.yml` → Run workflow

### 6.3 输出格式

- `.txt`：纯文本，适合阅读
- `.srt`：带时间戳字幕，可用播放器加载

## 八、常见问题

### Q1: 录制中途断了怎么办？

`fallback_upload.py` 会在工作流结束时（`if: always()`）自动上传所有已录制的文件，即使录制崩溃也不会丢失。

### Q2: 为什么有的文件显示的时间跨天了？

如果录制在 23:59 开始、00:30 结束，文件名中的时间戳可能跨天。`fallback_upload.py` 已移除了重命名逻辑，文件名保留录制时的时间戳，不会出现上传时间覆盖录制时间的问题。

### Q3: API Rate Limit 403 错误？

- GitHub Actions 的 `GITHUB_TOKEN` 每小时 1000 次请求
- 已优化 API 调用频率：刷新房间 120 秒/次，写状态 300 秒/次
- 约 42 次/小时，远低于限制
- 如仍报错，等待整点重置，或取消堆积的 workflow

### Q4: 如何查看直播实时状态？

前端页面会自动加载 `docs/live_status.json`，显示每个房间是否在线、是否在录制。

### Q5: 如何搜索发现新主播？

运行 `searcher.py`（需要 `DOUYIN_COOKIE`），自动搜索指定关键词的直播间，发现的新房间会自动追加到 `rooms.txt`。

### Q6: 时区设置？

- Runner 环境变量：`TZ=Asia/Shanghai`
- Python 代码：`ZoneInfo("Asia/Shanghai")`
- 前端页面：浏览器本地时区自动转换
- 所有时间戳均以中国上海时间（UTC+8）为准

## 九、维护建议

1. **定期检查** GitHub Actions 运行日志，关注是否有异常
2. **Token 管理**：GH_TOKEN 如过期需重新生成并更新 Secret
3. **房间清理**：定期清理不再直播的房间，减少资源消耗
4. **存储管理**：GitHub Release 文件较多时，可手动清理旧文件
5. **依赖更新**：关注 `funasr`、`playwright` 等依赖更新，提升转写质量
